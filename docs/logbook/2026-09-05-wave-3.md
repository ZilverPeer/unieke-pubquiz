## Observations (judgement)

- The pre-dispatch probe (running `tsx` against a renderer) paid for itself: an environment-level blocker was fixed on master in one commit instead of surfacing inside the implementer's tdd loop. Worth making a standing step: before dispatching an integrating ticket, run the smallest real command the ticket will need.
- The persist-before-write ordering bug is the kind that no acceptance criterion states and no green suite catches; the Standards reviewer found it by reading the flow against the ticket's intent ("a failure consumes no Items"). Keep asking Standards reviewers to check ordering and failure paths, not only structure.
- Seed-derived expectations in the brief were double-edged. They made the unsatisfiable case precise, but the zero-slack seed also made a sampler weakness (#22) visible only when two Quizzes were generated for one email. That is a real finding, not test flakiness; filing it instead of loosening the test was the right call, and the implementer's switch to a `single_category` proof kept the ticket honest.
- Platform gap between agents: the implementer worked in bash, the Spec reviewer in PowerShell, and only the latter hit the npm `--` forwarding problem. Having the Spec reviewer use the user's actual shell is what caught it; keep that.
- Spec #1 totals: eight PRs across waves 2 and 3 (incl. the #22 follow-up), every one needing exactly one fix round, zero merge conflicts. The pattern (pin interfaces, one Sonnet implementer per ticket in a worktree, Standards plus empirical Spec review, one bundled fix message to the original implementer) is stable enough to reuse for spec #2 without change.
