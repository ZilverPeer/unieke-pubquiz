## Friction log

- `@react-pdf/renderer` cannot be driven from plain `node`/`tsx` (deep import `@react-pdf/hyphenate` throws `ERR_PACKAGE_PATH_NOT_EXPORTED`); sample PDFs must be produced from inside vitest. Reported by the #7 implementer, then relayed to every PDF reviewer.
- `MessageKey` was not re-exported from the domain barrel, so the #7 implementer reached into `@/domain/messages/keys` (a Standards finding that was really an interface gap in the pinned commit).
- The #10 implementer reported all six tests green on the first run, i.e. no red-green churn; the tdd process was followed in form but the tests were written against a finished design.
- Standards review #18: duration expectations import `MUSIC_ROUND_GAP_SECONDS` from the module under test (partially tautological); pre-flight validation tests sit inside the ffmpeg skip guard for no reason; `-ar/-ac/-c:a/-b:a` output tail duplicated three times.

- Spec review #16 found that mixed-mode Category exhaustion throws a plain Error instead of returning a `GenerationFailure`; the pinned `categoryId: string` type had no way to express "no Category assignable", so the fix widens it to `string | null`.
- Spec review #19 empirically showed the no-repeat rule is case-sensitive on billing email (upper-cased lookup returned an empty set); neither the ticket nor CONTEXT.md had stated a normalisation rule. Standards review #19 flagged silent truncation of the pool query above PostgREST's 1000-row default; the implementer had only worked around it for the auxiliary translations query.
- Spec review #20 found the handout heading does not wrap for long category names, and that the circular number badges are original styling rather than the plain legacy look. The hand-rolled PNG encoder in the test (needed because @react-pdf dedupes identical image bytes) was judged disproportionate.
- The Standards reviewer for #20 spotted the same `MessageKey` deep import in the #9 branch while comparing siblings; the #17 Standards reviewer had missed it.

## Observations (judgement)

- Pinning interfaces, stubs, message keys and dependencies on master before dispatch worked: six parallel branches, zero conflicts, and the only interface change needed afterwards (`GenerationFailure.categoryId` nullable, `MessageKey` re-export) was small. Worth repeating for wave 3.
- Empirical Spec review earned its cost. Three of the six PRs had a defect the implementer's own green suite did not catch (Category exhaustion in #5, case-sensitive email in #6, heading overflow in #8), and each was found by a reviewer actually exercising the code, not by reading the diff.
- Standards reviewers vary. The #17 reviewer missed a deep import that the #20 reviewer found while comparing siblings; asking every Standards reviewer to diff against the sibling renderer would have caught it directly.
- One fix round per PR is the steady state; none needed a second. Bundling Standards and Spec findings into a single message to the original implementer (with its worktree context intact) was cheap and fast, typically 2-8 minutes per round.
- tdd discipline is uneven when the design is fully specified in the brief: #10 wrote tests against a finished design (all green first run). The fix rounds were explicitly asked to write the failing test first and reported red-then-green, which is the behaviour to keep requesting.
- Unit and integration suites are now split (`npm test` never needs the stack; `npm run test:integration` does). #11 should reuse that split rather than add a third mode.
