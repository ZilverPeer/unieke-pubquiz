## Process changes this wave

- **One shop instance per ticket, reused by the reviewer.** Shop tickets share `../Pubquiz-wt-shop`; the implementer starts wp-env from the worktree and leaves it running; the Spec reviewer proves the worktree is at the branch tip and reuses that instance instead of building its own; the orchestrator runs `shop:down` once at merge. (`docs/agents/orchestration.md`.)
- **Iterate one step, not the whole setup.** The `implement` skill: apply or verify a changed setup step by running only that step (`npx tsx -e "import('./scripts/shop/lib/<module>.ts').then(m => m.<fn>())"`), one full `shop:up` per ticket for the idempotency check right before pushing.
- **Foreground waiting.** Long commands run in the foreground with a large timeout; background only with a single blocking `until ...; do sleep 5; done` call; never no-op polling.
- **10-minute check-in** (Erik, 18:20): the cron check-in runs every 10 minutes instead of 30, and every deviation gets a line in the Drift log below.
- **Ticket #61** created: the WordPress side of `shop:up` in one `wp eval-file` bootstrap, target under 90 s, at most three WP-CLI invocations.
