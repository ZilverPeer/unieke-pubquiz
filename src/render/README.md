Rendering: turns a `Composition` plus the Items' full content and a `Locale` into the four Deliverable files (Quizmaster PDF, Picture Round handout PDF, Answer sheet PDF, Music Round MP3) as byte buffers, one renderer per file. May import only `src/domain`. Never imports `src/repository`. This ticket adds the shared branded PDF page shell (`src/render/pdf/shell.tsx`) and its registered fonts (`src/render/pdf/fonts/`); the four renderers take a `QuizContent` and return a `Buffer`: `renderQuizmasterPdf` (#7), `renderPictureHandoutPdf` (#8), `renderAnswerSheetPdf` (#9), `renderMusicRoundMp3` (#10), one file each, re-exported from `index.ts`.

## The zip (ticket #73)

The module's actual **Deliverable** output is one zip per Quiz, not the four loose files: `buildQuizZip` (`quiz-zip.ts`) takes the four rendered files (`GeneratedQuizFiles`, `src/scripts/generate-quiz.ts`, imported type-only so this stays a compile-time-only dependency, never a runtime one) and zips them with [`fflate`](https://github.com/101arrowz/fflate)'s `zipSync` under their existing fixed names (`quizmaster.pdf`, `picture-handout.pdf`, `answer-sheet.pdf`, `music-round.mp3`) -- unchanged, so the quizmaster PDF, the handout, the answer sheet and the MP3 stay recognisable once unzipped. The archive itself is named and stored as a single `quiz.zip` per Quiz (`DELIVERABLE_FILES`, `quizZipFilename`, `src/domain/orders.ts`) -- that naming is the caller's job (the worker for Storage, the download route for the browser), not this module's; `buildQuizZip` only builds the bytes. The renderers themselves are unchanged by this ticket -- no renderer knows about zipping.
