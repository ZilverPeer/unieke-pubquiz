Sampling: turns a `QuizRequest` plus an in-memory Item pool into a `Composition` (or a `GenerationFailure`), applying the no-repeat, Category, Difficulty, and no-duplicate-Subsubcategory rules. Pure, no I/O. May import only `src/domain`. Must never import `src/repository` or `src/render`.

## Behaviour

- **Categories**: `single_category` mode uses the first defined entry of `categoryPicks` for all 8 slots (throws if none is defined). `mixed` mode honours each defined pick for its slot and fills every unassigned slot with a distinct Category drawn from the pool's Categories (never a pick, never reused across slots); the random source chooses which. A duplicate Category across `mixed` mode's picks throws (invalid input, not a `GenerationFailure`).
- **Filling a slot**: for a single requested Difficulty, up to `ITEMS_PER_SLOT` (10) Items are chosen, at most one per Subsubcategory, so a shortfall only happens when there are genuinely fewer than 10 eligible Subsubcategories. `mixed` Difficulty splits the 10 as 4/3/3 across easy/medium/hard - which level gets 4 is chosen by the random source - while the no-shared-Subsubcategory rule still applies across all three levels combined. `excludedItemIds` and Items without a translation for `request.locale` are never eligible. Final position order within a slot is randomised.
- **Failure**: the first slot (in slot order) that can't reach 10 Items fails the whole Quiz, returning `{ ok: false, failure: { slotIndex, categoryId, shortfall } }` where `shortfall` is how many Items short of 10 the slot ended up.
- **Determinism**: the same seed (via `createSeededRandom`) always yields the same `Composition` for the same input; a different seed generally yields a different one.
