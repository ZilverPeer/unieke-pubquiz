Sampling: turns a `QuizRequest` plus an in-memory Item pool into a `Composition` (or a `GenerationFailure`), applying the no-repeat, Category, Difficulty, and no-duplicate-Subsubcategory rules. Pure, no I/O. May import only `src/domain`. Must never import `src/repository` or `src/render`.

## Behaviour

- **Categories**: `single_category` mode uses the first defined entry of `categoryPicks` for all 8 slots (throws if none is defined). `mixed` mode honours each defined pick for its slot and fills every unassigned slot with a distinct Category drawn from the pool's Categories (never a pick, never reused across slots); the random source chooses which. A duplicate Category across `mixed` mode's picks throws (invalid input, not a `GenerationFailure`). If the pool doesn't have enough distinct Categories left to assign to every remaining unassigned slot, that is a content shortfall, not a caller error: it returns a `GenerationFailure` for the first such slot, with `categoryId: null` and `shortfall` set to how many slots from that one onward are left without a Category.
- **Filling a slot**: a single requested Difficulty is a quota of `ITEMS_PER_SLOT` (10) Items of that level; `mixed` Difficulty is a quota of 4/3/3 across easy/medium/hard - which level gets 4 is chosen by the random source. Either way the quota is expanded into one "quota slot" per requested Item and matched to Subsubcategories by an exact maximum bipartite matching (`matching.ts`, Kuhn's algorithm): a quota slot of Difficulty `d` has an edge to every Subsubcategory with at least one eligible Item of Difficulty `d`, and the matching assigns each quota slot to a distinct Subsubcategory wherever possible, honouring the no-shared-Subsubcategory rule across the whole slot (all three Difficulty levels combined, for `mixed`). A shortfall is reported only when no full assignment exists at all - not from an unlucky greedy per-Difficulty-level pick order that could exhaust a Subsubcategory a later level needed even though a valid overall assignment existed. `excludedItemIds` and Items without a translation for `request.locale` are never eligible. Final position order within a slot is randomised.
- **Failure**: the first slot (in slot order) that can't be filled fails the whole Quiz, returning `{ ok: false, failure: { slotIndex, categoryId, shortfall } }`. `categoryId` is the slot's Category and `shortfall` is how many Items short of 10 it ended up when the slot had a Category but ran out of eligible Items; `categoryId` is `null` and `shortfall` is the count of un-categorised slots from `slotIndex` onward when the pool ran out of distinct Categories before every slot in `mixed` mode had one.
- **Determinism**: the same seed (via `createSeededRandom`) always yields the same `Composition` for the same input; a different seed generally yields a different one.
